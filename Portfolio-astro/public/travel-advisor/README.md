# Gredin Travel Advisor (template)

Modern rebuild of `../Website3` (Travelly), grown into a small travel
platform: a home page, a destinations index, and a guide page for each of
eight cities (London, Paris, Barcelona, Valencia, Curaçao, Antigua,
San Diego, New York City). Static HTML/CSS plus JavaScript component
classes.

## Structure

```
index.html                  home: hero, how it works, destinations, contact form
destinations/index.html     all destinations, grouped by region   (generated)
destinations/<slug>/        one guide per destination             (generated)
css/style.css               tokens, layout, components, responsive rules
js/data.js                  site settings and home page content
js/destinations.js          ALL destination content (one entry per city)
js/core.js                  Component base class, html`` escaping, link()
js/lib/seasons.js           Seasons model: monthly ratings -> "May–Sep"
js/lib/photo.js             Photo: responsive <img> markup from one data entry
js/lib/slideshow.js         Slideshow: timing/state for the photo hero
js/components/*.js          one class per UI piece
js/main.js                  loads the content and registers the components
fonts/, img/                self-hosted fonts (OFL) and images
```

The pages under `destinations/` are generated by
`../../tools/build-guides.mjs` (from the Portfolio-astro root:
`npm run guides`). It also runs automatically before every
`npm run build`, so Netlify always regenerates them. Edit the data, not
the generated HTML.

## Adding or editing a destination

1. Add an entry to `js/destinations.js` (copy an existing one; the key is
   the URL slug) and add the slug to `destinationOrder`.
2. Run `npm run guides`.

Each entry has its own colour (`accent`, plus `accentInk` for text on it,
which should have at least 4.5:1 contrast), a 12-month `seasons` rating,
neighbourhoods, transport tips, a sample itinerary, and "before you go"
basics. Photos are all optional, and decide which header a guide gets:

| Field | Effect | Example |
| --- | --- | --- |
| `scenes` | full-bleed photo slideshow header with a labelled scene index | London, Valencia, Barcelona |
| `photo` | one photo beside a colour header | New York |
| neither | typographic header in the city's colour | Paris and the rest |
| `cardPhoto` | photo on the city's destination card | London, Valencia, Barcelona |
| `gallery` | "From our trip" captioned photo mosaic | Valencia, Barcelona |
| `dayTrips` | "Worth the trip out": text beside a photo pair | London (Kew Gardens) |

## Photos

Each photo is stored at three widths, `img/<city>/<name>-640.webp`,
`-960.webp` and `-1600.webp`, and referenced in the data by its base path
(`file: "img/london/london-thames"`) plus the largest file's real `width`
and `height`. `js/lib/photo.js` builds the responsive `srcset`; an
optional `position` ("50% 30%") sets how it crops.

The travel photos are our own, refined with
`../../tools/photos/refine-photos.py`: haze and colour correction, crops
(for example to remove the phone's "Galaxy S24 Ultra" watermark), blurred
number plates, and all EXIF/GPS metadata stripped. Run it on new photos
with a small JSON file of crop/tone settings (usage is in the script).

The "before you go" facts are written for US passport holders and were
checked in November 2026. Entry rules change: re-check them (UK ETA, EU
EES/ETIAS, Curaçao DI card, ArriveAntigua) before relying on them.

## Components

Each is a class extending `Component` (which extends `HTMLElement`), used
as a custom tag that reads its content by path via `data-from`:

| Tag | Class | Renders |
| --- | --- | --- |
| `<gta-header>` | `SiteHeader` | brand, nav, CTA; `open()` / `close()` / `toggle()` for the phone menu; marks the current section |
| `<gta-footer>` | `SiteFooter` | footer and links |
| `<gta-itinerary>` | `ItineraryCard` | a sample plan drawn as a route (home hero and every guide) |
| `<gta-steps>` | `StepList` | numbered "How it works" steps |
| `<gta-destination>` | `DestinationCard` | one city card in its own colour |
| `<gta-destination-grid>` | `DestinationGrid` | all cards; `grouped` for region headings, `data-exclude` to skip one |
| `<gta-guide>` | `GuidePage` | a full guide, composed of the components below; picks the header style from the data |
| `<gta-photo-hero>` | `PhotoHero` | full-bleed cross-fading photos with a scene index, using `Slideshow` and `Photo` |
| `<gta-gallery>` | `PhotoGallery` | "From our trip" mosaic; wide photos span two columns |
| `<gta-day-trips>` | `DayTrips` | places outside the city, text beside a photo pair |
| `<gta-seasons>` | `SeasonChart` | the 12-month "When to go" strip, using `Seasons` |
| `<gta-definitions>` | `DefinitionList` | term + description pairs (base class) |
| `<gta-places>` | `PlaceList` | neighbourhoods (extends `DefinitionList`) |
| `<gta-facts>` | `FactList` | "Before you go" (extends `DefinitionList`) |
| `<gta-included>` | `IncludedList` | what every booking covers (extends `DefinitionList`) |

`ContactForm` is a plain class (not a custom element) that wraps the
static form; it fills "Where to" from a guide's "Plan a trip to …" link
(`?to=Paris#contact`).

To add a component: create a class with a `static tag`, a `render(data)`
that returns an ``html`…` `` template, and optional `afterRender()` for
behaviour; then add it to the list in `main.js`.

Links and image paths in data are written relative to the site
(`"destinations/"`, `"img/x.webp"`); `link()` in `core.js` prefixes
`site.base` so they work from any page depth. Moving the template means
changing `site.base` in `data.js`.

## Deliberately not components

- **Home hero headline and intro** stay in `index.html` so they're in the
  page before any JS runs.
- **Contact form** stays in `index.html` because Netlify only detects
  forms present in the deployed HTML (`data-netlify="true"`). Submissions
  appear under the site's Forms tab as `travel-advisor`.

## Constraints from the portfolio site

The portfolio's `_headers` sends a strict CSP (`script-src 'self'`,
`style-src 'self'`, `font-src 'self'`): no inline scripts or styles, no
font CDNs. City colours are therefore set from script via the CSSOM
(`element.style.setProperty`), which the CSP allows, rather than as
`style=""` attributes, which it blocks.

## Without JavaScript

The header, destination cards, guides, and footer render from JS. With JS
off, guide pages show a `<noscript>` fallback (name and intro), and the
home hero and contact form still work.
